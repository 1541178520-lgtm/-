# 学生成长档案系统 V1 设计规格

## 目标与范围

为教育机构管理员提供一个内部使用的网站，为每名学生持续记录基本资料、标签、考试成绩、晚辅反馈和分科课程反馈，并通过浏览器打印为正式的《学生成长档案》。V1 仅包含任务书明确列出的管理员功能，不包含 AI、家长端、学生端、微信小程序、收费、排课、消课、CRM、在线聊天、成绩预测、知识库或复杂权限。

所有项目代码、文档、迁移和测试均放在工作区根目录的 `学生成长档案系统` 文件夹内，不修改相邻的现有微信小程序代码。

## 技术方案评估

### 方案 A：React SPA + 单一 Cloudflare Worker + D1（采用）

Vite 构建 React/TypeScript 单页应用，Cloudflare Vite 插件把静态资源和 Worker API 作为一个部署单元发布。Worker 仅处理 `/api/*`，D1 保存业务数据、管理员密码摘要和会话。该方案没有跨域配置，也不需要 SSR，开发、测试和部署最简单。

### 方案 B：React Router 全栈 SSR

加载器和表单动作可以统一页面数据流，但本项目是登录后的内部后台，不需要 SEO 或首屏 SSR。引入服务端路由、序列化边界和水合逻辑会增加 V1 复杂度，因此不采用。

### 方案 C：独立前端与 API Worker

服务边界更强，但需要两个部署单元、跨域和独立环境配置。对轻量内部系统没有实际收益，因此不采用。

## 总体架构

- 前端：React、TypeScript、React Router、Tailwind CSS；PC 采用固定左目录加右档案页，窄屏切换为可开合的学生目录。
- 后端：一个 Cloudflare Worker，使用轻量路由模块组织认证、学生、标签、成绩、晚辅、课程和打印数据接口。
- 数据库：Cloudflare D1；所有业务表使用外键与必要索引，删除学生时级联清理该学生的关联数据。
- 验证：共享的字段规则在服务端强制执行；客户端重复关键规则以提供即时提示，但客户端验证不作为安全边界。
- 部署：Cloudflare Vite 插件把 SPA 静态资源和 Worker 一次部署。`/api/*` 始终先进入 Worker，其余路径使用 SPA fallback。

## 数据模型

### 管理员与会话

- `admins`：`id`、唯一 `username`、`password_hash`、`password_salt`、`password_iterations`、`created_at`、`updated_at`。
- `sessions`：随机会话令牌的 SHA-256 摘要、管理员 ID、过期时间、创建时间；数据库不保存可直接复用的明文令牌。
- 初始管理员通过仅在尚无管理员时可用的 CLI 初始化命令创建，密码从交互式输入或环境变量读取，不写入仓库。

### 档案数据

- `students`：姓名、年级、学校、入学日期、备注及创建/更新时间。
- `tags`：唯一标签名及创建/更新时间。
- `student_tags`：学生与标签的唯一多对多关系。
- `scores`：考试名称、考试日期、语文、数学、英语、物理、化学、备注及时间戳；各科成绩允许为空，非空时必须为 0–150 的数字。
- `study_records`：记录日期、晚辅正文及时间戳。
- `course_records`：固定科目、记录日期、课程内容、教师反馈及时间戳。
- 日期存为 `YYYY-MM-DD`；系统时间存为 UTC ISO 8601 字符串，由前端按本地时区显示。
- 同一日期的多条记录以日期升序、创建时间升序、ID 升序形成稳定顺序。

固定年级允许填写常用值或自定义文本，以兼容机构未来出现小学、高中或非标准班级；固定课程科目仅为：语文、数学、英语、物理、化学、自然拼读、剑桥。

## API 与安全边界

- `POST /api/auth/login` 校验用户名和密码，成功后设置 `HttpOnly`、`SameSite=Lax`、生产环境 `Secure` 的会话 Cookie。
- `POST /api/auth/logout` 删除服务端会话并清除 Cookie；`GET /api/auth/me` 返回当前管理员或 401。
- 所有学生、标签、成绩、晚辅、课程和打印数据接口都必须先通过服务端会话中间件；不仅写接口，读取学生数据也禁止匿名访问。
- 密码使用带随机盐的 PBKDF2-SHA-256 摘要；比较时采用固定时长字节比较。登录失败统一返回相同错误，不泄漏用户名是否存在。
- 变更接口只接受 JSON，执行长度、枚举、日期和数值范围校验；错误统一为 `{ error: { code, message, fields? } }`。
- Cookie 会话接口校验同源请求的 `Origin`；所有 SQL 使用绑定参数；响应设置 `Cache-Control: no-store` 和必要安全响应头。
- 删除学生、标签或记录必须由前端二次确认；服务端仍独立校验身份和资源归属。

## 页面与交互设计

### 登录页

居中的纸张式登录面板，仅包含用户名、密码、提交按钮和错误提示。登录成功进入档案主页；未登录访问任何应用路由都回到登录页。

### 档案工作区

左侧是米白色档案目录：顶部搜索框和“新增学生”，下方按年级分组并可折叠。学生姓名旁显示少量标签；搜索采用姓名包含匹配并即时过滤。右侧是白色纸张区域，顶部展示学生资料、标签、“编辑学生”“删除学生”“打印档案”。

窄屏下左栏变为抽屉，顶部提供“学生目录”按钮；表单、分页和记录正文保持可触控与可阅读。

### 成绩

打开学生后默认进入成绩页。记录按考试日期从旧到新显示为纵向时间轴，每次考试展示非空科目及备注。新增和编辑使用同一对话框，所有科目可留空；支持删除。

### 晚辅笔记

每次只显示一页，内容区域使用轻微纸张纹理、页眉日期和页码。按旧到新排序，提供上一页、下一页、新增、编辑、删除。新增表单默认今天，只有日期和大文本框；编辑日期后重新定位到该记录的新排序位置。

### 课程笔记

先展示七个固定科目入口，选择后进入与晚辅一致的单页笔记体验。表单包含日期、课程内容和教师反馈，日期默认今天；切换科目时只请求并显示该科目数据，防止混淆。

### 标签管理

学生编辑区域可勾选多个现有标签，并进入简洁的标签管理对话框新增、改名、删除标签。删除仍被学生使用的标签时提示影响数量，确认后删除关联关系。标签名去除首尾空格并保持唯一。

## 打印档案

`/students/:studentId/print` 是专用打印路由，一次加载该学生的完整档案：封面、成绩、全部晚辅、仅有记录的课程章节。页面提供屏幕上可见的“返回”和“打印/另存为 PDF”按钮；`@media print` 隐藏这些按钮及所有后台导航。

打印样式采用 A4、合理页边距、章节分页、页脚页码和学生姓名。每条成绩或笔记记录设置 `break-inside: avoid`，空课程不生成章节。浏览器原生 `window.print()` 负责打印或另存为 PDF。

## 错误处理

- 401：前端清空会话状态并回到登录页。
- 404：学生或记录不存在时显示明确空状态，返回学生目录，不保留失效编辑表单。
- 409：标签重名或并发删除造成的冲突在表单旁提示。
- 422：字段错误显示在对应输入项；不丢失已填写内容。
- 5xx/网络失败：保留输入，显示可重试提示；成功后才关闭表单并刷新数据。

## 测试策略与验收证据

### Worker 集成测试

使用 Cloudflare Workers 的 Vitest 集成池和临时 D1：执行真实迁移，测试初始化管理员、密码摘要、登录/注销、会话过期、匿名读写拒绝、同源保护，以及所有业务实体的 CRUD、排序、过滤、级联删除和验证错误。

### 前端测试

使用 Vitest、Testing Library 和 jsdom 测试学生按年级分组/搜索、成绩空科目展示、笔记分页、科目隔离、表单验证和 401 跳转。

### 端到端测试

使用 Playwright 启动本地 Worker/D1，完成任务书验收流程：创建和修改学生及标签；录入三次成绩并编辑删除；录入十条晚辅并修改日期；分别录入数学 5 条、英语 3 条、物理 2 条；刷新验证持久化和科目隔离；打开打印路由验证章节与操作控件的打印隐藏样式；退出后验证页面和 API 均拒绝访问。

### 构建与视觉验证

最终必须运行类型检查、Lint、全量单元/集成测试、Playwright 端到端测试和生产构建。使用浏览器分别检查桌面与移动视口，并检查打印媒体截图或 PDF，确认无后台按钮、分页合理且记录不被截断。

## 部署与交付

仓库提供完整的 `wrangler.jsonc`、D1 迁移、环境变量示例、初始化管理员命令及部署说明。若当前机器已有可用 Cloudflare 登录与账户授权，则创建远程 D1、应用迁移、设置秘密并部署；若没有凭据，则本地全功能验证仍继续完成，实际发布仅保留为需要账户授权的外部步骤，不使用模拟上线替代。

## 非目标

不添加任务书 V1 排除项；不添加复杂图表、动画、服务端 PDF、文件上传、审计后台、多租户、多角色或自助注册。
